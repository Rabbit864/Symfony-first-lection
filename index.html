Symfony

Что такое Symfony

Symfony — это популярный PHP-фреймворк с открытым исходным кодом, который предназначен для разработки сложных веб-приложений и API. Он предоставляет мощный набор компонентов, которые позволяют разработчикам быстро строить качественные и масштабируемые веб-приложения. Symfony ориентирован на гибкость и расширяемость, и часто используется для создания крупных и сложных веб-проектов, таких как корпоративные сайты, интернет-магазины, платформы для работы с данными и многие другие.

Что такое Framework

Фреймворк (Framework) — это набор готовых инструментов и библиотек, которые предоставляют структуру и шаблоны для разработки программного обеспечения. Фреймворк упрощает разработку, обеспечивая решение распространённых задач, таких как обработка запросов, маршрутизация, взаимодействие с базой данных, аутентификация и другие.

Установка Symfony

            
              1) composer create-project symfony/skeleton:"6.4.x" my_project_directory
              2) cd my_project_directory
              3) composer require webapp

Twig

Что такое Twig

Twig — это шаблонизатор для PHP, который используется для создания HTML-шаблонов. Он помогает разделить логику работы с данными и представление этих данных на странице.

Twig в symfony

Все шаблоны обычно находятся в папке templates/ в корне проекта Symfony, и для рендеринга страницы достаточно в контроллере использовать метод render()

Синтаксис функции render

            
              $this->render(string $view, array $parameters = [])
  • $view — это путь к шаблону, который ты хочешь отрендерить. В Symfony по умолчанию это путь относительно папки templates/. Например, если у вас шаблон templates/example/index.html.twig, то параметр $view будет выглядеть так: 'example/index.html.twig'
  • $parameters — это массив данных, которые вы передаете в шаблон. Эти данные доступны в шаблоне через переменные. Например, если вы передаете в шаблон переменную name, то в шаблоне вы можете использовать её как {{ name }}

Пример использования в функции

            
              class ExampleController extends AbstractController
              {
                  public function index(): Response
                  {
                      // Данные, которые мы передаем в шаблон
                      $name = 'Иван';

                      // Вызов функции render для рендеринга шаблона с переданными данными
                      return $this->render('example/index.html.twig', [
                          'superName' => $name,
                      ]);
                  }
              }

Роутинг

Роутинг

В Symfony роутинг отвечает за определение того, как HTTP-запросы должны быть направлены к определенным контроллерам в вашем приложении. Роутинг — это процесс сопоставления URL с контроллерами, а также параметрами, которые можно передать этим контроллерам.

Создание контроллера

Для создания контроллера используйте команду:

            
              php bin/console make:controller YourController

Роутинг

            
              namespace App\Controller;

              use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
              use Symfony\Component\Routing\Annotation\Route;

              class ExampleController extends AbstractController
              {
                  #[Route('/hello', name: 'hello')]
                  public function hello(string $name)
                  {
                      return $this->render('hello.html.twig');
                  }
              }

#[Route('/hello', name: 'hello')] — атрибут маршрута, который привязывает URL. В данном примере когда пользователь зайдет по урлу /hello ему вернется содержимое шаблона hello.html.twig. Имя урла должно быть уникальным

Роутинг с параметром

            
              namespace App\Controller;

              use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
              use Symfony\Component\Routing\Annotation\Route;

              class ExampleController extends AbstractController
              {
                  #[Route('/greet/{name}', name: 'greet_optional', defaults: ['name' => 'Guest'])]
                  public function greetOptional(string $name)
                  {
                      return $this->render('greet_optional.html.twig', [
                          'name' => $name
                      ]);
                  }
              }

Когда пользователь посещает /greet/John, значение John передается в метод как параметр $name.

По умолчанию все параметры имеют тип string, но вы можете менять тип меняя тип в аргументах функции

В атрибуте маршрута установлено значение по умолчанию для параметра name — "Guest", если параметр не будет передан в URL.

Формы html

Основные элементы формы

  • <form> — корневой элемент формы, который определяет её границы.

Request в Symfony

Класс Request

В Symfony класс Request является частью компонента HttpFoundation и представляет собой объект, который инкапсулирует все данные HTTP-запроса. Он предоставляет удобный интерфейс для доступа к данным запроса, таким как параметры GET и POST, заголовки, куки, файлы и т. д.

Пример получения GET запроса

            
              $request->query->get('param_name'); // Получить значение параметра 'param_name' из GET-запроса

Чтобы получить параметры из строки запроса, используйте метод query->get()

Пример получения POST запроса

            
              $request->request->get('param_name'); // Получить значение параметра 'param_name' из POST-запроса

Чтобы получить параметры из POST-запроса, используйте метод request->get()

Пример обработки POST-запроса в контроллере

            
              // src/Controller/UserController.php
              namespace App\Controller;
              
              use Symfony\Component\HttpFoundation\Request;
              use Symfony\Component\HttpFoundation\Response;
              use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
              use Symfony\Component\Routing\Annotation\Route;
              
              class UserController extends AbstractController
              {
                  /**
                   * @Route("/register", name="user_register")
                   */
                  public function register(Request $request): Response
                  {
                      // Получаем данные из POST-запроса
                      $name = $request->request->get('name');
                      $email = $request->request->get('email');
                      
                      // Простая валидация
                      if (empty($name) || empty($email)) {
                          return new Response('Пожалуйста, заполните все поля.');
                      }
                      
                      // Обработка данных (например, сохранить в базу данных)
                      // В данном примере просто выводим их
                      return new Response("Имя: $name, Email: $email");
                  }
              }

Пример обработки GET-запроса в контроллере

            
              // src/Controller/GreetController.php
              namespace App\Controller;

              use Symfony\Component\HttpFoundation\Request;
              use Symfony\Component\HttpFoundation\Response;
              use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
              use Symfony\Component\Routing\Annotation\Route;

              class GreetController extends AbstractController
              {
                  /**
                  * @Route("/greet", name="greet", methods={"GET"})
                  */
                  public function greet(Request $request): Response
                  {
                      // Получаем параметры из строки запроса
                      $name = $request->query->get('name', 'Гость'); // Параметр 'name', по умолчанию 'Гость'
                      $age = $request->query->get('age', 'неизвестен'); // Параметр 'age', по умолчанию 'неизвестен'

                      // Создаем ответ с использованием данных из запроса
                      $message = sprintf("Привет, %s! Тебе %s лет.", $name, $age);

                      // Возвращаем ответ
                      return new Response($message);
                  }
              }

Сущности и Миграции

Сущности и Миграции

В Symfony миграции и сущности (Entity) используются в связке с Doctrine, что позволяет эффективно работать с базой данных. Миграции — это способ управления изменениями в структуре базы данных, а сущности — это классы, которые отражают таблицы в базе данных. Давайте разберемся, как это работает на практике.

Сущности(Entities)

Сущности в Doctrine представляют собой объекты, которые отражают таблицы в базе данных. Сущности связываются с таблицами через аннотации или YAML/XML-конфигурации.

Команда для создания сущностей

            
              php bin/console make:entity

Пример сущности

Допустим, мы создаем сущность User, которая будет представлять пользователя в нашей системе. 

            
              // src/Entity/User.php
              namespace App\Entity;
              
              use Doctrine\ORM\Mapping as ORM;
              
              #[ORM\Entity(repositoryClass: "App\Repository\UserRepository")]
              class User
              {
                  #[ORM\Id]
                  #[ORM\GeneratedValue]
                  #[ORM\Column(type: "integer")]
                  private int $id;
              
                  #[ORM\Column(type: "string", length: 100)]
                  private string $name;
              
                  #[ORM\Column(type: "string", length: 100)]
                  private string $email;
              
                  // Геттеры и сеттеры для каждого свойства
                  public function getId(): int
                  {
                      return $this->id;
                  }
              
                  public function getName(): string
                  {
                      return $this->name;
                  }
              
                  public function setName(string $name): self
                  {
                      $this->name = $name;
                      return $this;
                  }
              
                  public function getEmail(): string
                  {
                      return $this->email;
                  }
              
                  public function setEmail(string $email): self
                  {
                      $this->email = $email;
                      return $this;
                  }
              }

Атрибуты сущнсоти

В предыдущем примере мы В этом примере мы используем атрибуты для задания метаданных сущности. Это делается через синтаксис #[ATTRIBUTES], который применяется к свойствам класса и самому классу.

Пояснение к атрибутам

  • #[ORM\Entity(repositoryClass: "App\Repository\UserRepository")]: Это атрибут, который указывает, что класс является сущностью Doctrine и связывается с репозиторием UserRepository.
  • #[ORM\Id]: Обозначает, что это поле является идентификатором (первичным ключом).
  • #[ORM\GeneratedValue]: Указывает, что значение этого поля будет генерироваться автоматически.
  • #[ORM\Column(type: "integer")]: Указывает, что тип столбца в базе данных будет integer.
  • #[ORM\Column(type: "string", length: 100)]: Указывает, что столбец будет строкой (VARCHAR) длиной 100 символов.

Дополнение

  • Мы используем типы данных PHP для определения свойств (например, int, string), которые будут соответствовать соответствующим типам в базе данных.
  • Для работы с полями сущности (например, для получения и изменения значений полей) создаются стандартные геттеры и сеттеры.

EntityManager

EntityManager

В Symfony, при работе с Doctrine ORM для манипуляции сущностями, используется класс EntityManager. Этот класс отвечает за взаимодействие с базой данных: создание, обновление, удаление, а также выполнение запросов.

Частые команды в EntityManager

EntityManager — это центральный объект в Doctrine ORM, который управляет жизненным циклом сущностей, выполняет операции сохранения, обновления и удаления, а также предоставляет интерфейсы для выполнения запросов.

  • persist($entity) — сохраняет новую сущность
  • flush() — синхронизирует все изменения, сделанные в сущностях, с базой данных.
  • remove($entity) — удаляет сущность.

Пример создания сущности

            
              // src/Controller/UserController.php
              namespace App\Controller;

              use App\Entity\User;
              use Doctrine\ORM\EntityManagerInterface;
              use Symfony\Component\HttpFoundation\Request;
              use Symfony\Component\HttpFoundation\Response;
              use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
              use Symfony\Component\Routing\Annotation\Route;

              class UserController extends AbstractController
              {
                  /**
                  * @Route("/user/create", name="user_create", methods={"POST"})
                  */
                  public function create(Request $request, EntityManagerInterface $entityManager): Response
                  {
                      // Получаем данные из POST-запроса
                      $name = $request->request->get('name');
                      $email = $request->request->get('email');

                      // Создаем новый объект User
                      $user = new User();
                      $user->setName($name);
                      $user->setEmail($email);

                      // Сохраняем сущность
                      $entityManager->persist($user); // Говорим Doctrine, что сущность должна быть сохранена
                      $entityManager->flush(); // Применяем изменения и сохраняем данные в базе

                      return new Response('Пользователь создан с ID: ' . $user->getId());
                  }
              }

Пример обновлении сущности

            
              // src/Controller/UserController.php
              namespace App\Controller;

              use App\Entity\User;
              use Doctrine\ORM\EntityManagerInterface;
              use Symfony\Component\HttpFoundation\Request;
              use Symfony\Component\HttpFoundation\Response;
              use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
              use Symfony\Component\Routing\Annotation\Route;

              class UserController extends AbstractController
              {
                  /**
                  * @Route("/user/{user}", name="user_update", methods={"PUT"})
                  */
                  public function update(User $user, Request $request, EntityManagerInterface $entityManager): Response
                  {
                      // Получаем новые данные из PUT-запроса
                      $name = $request->request->get('name');
                      $email = $request->request->get('email');

                      // Обновляем данные пользователя
                      $user->setName($name);
                      $user->setEmail($email);

                      // Сохраняем изменения
                      $entityManager->flush();  // Применяем изменения в базе данных

                      return new Response('Пользователь с ID ' . $user->getId() . ' был обновлен.');
                  }
              }

Пример удаления сущности

            
              // src/Controller/UserController.php
              namespace App\Controller;

              use App\Entity\User;
              use Doctrine\ORM\EntityManagerInterface;
              use Symfony\Component\HttpFoundation\Response;
              use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
              use Symfony\Component\Routing\Annotation\Route;

              class UserController extends AbstractController
              {
                  /**
                  * @Route("/user/{user}", name="user_delete", methods={"DELETE"})
                  */
                  public function delete(User $user, EntityManagerInterface $entityManager): Response
                  {
                      // Удаляем сущность
                      $entityManager->remove($user);  // Помечаем сущность для удаления
                      $entityManager->flush();  // Применяем изменения в базе данных

                      return new Response('Пользователь с ID ' . $user->getId() . ' был удален.');
                  }
              }

Репозиторий

В Symfony, репозитории (Repositories) используются для выполнения запросов к базе данных.

Репозиторий может использоваться для выполнения запросов к базе данных, таких как:
  • Поиск сущностей.
  • Фильтрация данных
  • Выполнение сложных запросов.

Репозитории находятся в папке src/Repository и связаны с сущностями через Doctrine

Пример использования EntityManager и Repository внутри контроллера 

            
              // src/Controller/UserController.php
              namespace App\Controller;

              use App\Entity\User;
              use App\Repository\UserRepository;
              use Doctrine\ORM\EntityManagerInterface;
              use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
              use Symfony\Component\HttpFoundation\Response;
              use Symfony\Component\Routing\Annotation\Route;

              class UserController extends AbstractController
              {
                  private $userRepository;
                  private $entityManager;

                  public function __construct(UserRepository $userRepository, EntityManagerInterface $entityManager)
                  {
                      $this->userRepository = $userRepository;
                      $this->entityManager = $entityManager;
                  }

                  
                  #[Route('/users', name: "user_index")]
                  public function index(): Response
                  {
                      // Получаем всех пользователей через репозиторий
                      $users = $this->userRepository->findAll();

                      // Возвращаем результат в виде ответа
                      return $this->render('user/list.html.twig', [
                          'users' => $users,
                      ]);
                  }

              }

Метод find

Метод find() используется для поиска сущности по её ID (или первичному ключу) 

            
              $user = $userRepository->find($id);

Метод ищет сущность по её идентификатору (первичному ключу). В результате возвращается объект сущности, если он найден, или null, если сущность с таким идентификатором не существует.

Метод findBy

Метод findBy() используется для поиска сущностей по нескольким критериям. Это позволяет вам получить список сущностей, которые соответствуют определённым параметрам. Вы можете передавать массив критериев, а также настраивать порядок сортировки и лимит выборки. 

            
              $users = $userRepository->findBy(['name' => 'John', 'email' => 'john@example.com']);

Этот метод позволяет искать все сущности, которые соответствуют набору переданных критериев.

Ещё один пример использования findBy

            
              // Находим пользователей с именем "John"
              $users = $userRepository->findBy(['name' => 'John']);  

              // Выведем имена всех найденных пользователей
              foreach ($users as $user) {
                  echo $user->getName();
              }

Пример findBy с доп. параметрами

            
              // Находим пользователей с именем "John", сортируем по дате создания, ограничиваем 10 результатами
              $users = $userRepository->findBy(
                  ['name' => 'John'],           // Условие поиска
                  ['createdAt' => 'DESC'],      // Сортировка по дате создания (по убыванию) (аналог ORDER BY)
                  10,                           // Лимит на 10 пользователей (аналог LIMIT)
                  0                             // Смещение (аналог OFFSET)
              );

              foreach ($users as $user) {
                  echo $user->getName();
              }

Метод findOneBy()

Метод findOneBy() используется для поиска одной сущности, которая соответствует переданным критериям. В отличие от findBy(), который возвращает массив сущностей, findOneBy() возвращает только одну сущность или null, если такая сущность не найдена 

            
              $user = $userRepository->findOneBy(['email' => 'john@example.com']);

тот метод ищет одну сущность, которая соответствует переданным критериям (например, email). Если таких сущностей несколько, метод возвращает первую, которая подходит под условия

Метод findAll

Функция findAll() в Doctrine используется для получения всех записей из таблицы, которая соответствует определенной сущности 

            
              // Получаем всех пользователей из базы данных
              $users = $userRepository->findAll();

В этом примере мы используем findAll() для извлечения всех пользователей. Результатом будет массив объектов User, которые затем передаются в шаблон для отображения.

Query Builder

QueryBuilder в Doctrine — это мощный инструмент для создания динамических SQL-запросов. Он позволяет строить запросы на уровне PHP, избегая необходимости писать сложный SQL вручную. Это также позволяет строить более гибкие запросы с возможностью безопасной работы с параметрами (что помогает избежать SQL-инъекций) и поддерживает работу с сущностями Doctrine.

Пример использования query builder

            
              $qb = $userRepository->createQueryBuilder('u');
              $qb->where('u.name = :value')
                ->setParameter('value', $value);
                
              $query = $qb->getQuery(); // Аналогичен SELECT * FROM users u where u.name = value 
              $results = $query->getResult(); // массив объектов User

Where

Метод where() добавляет условие для запроса. Вы можете добавлять дополнительные условия с помощью andWhere() или orWhere(). 

            
              $qb->where('u.name = :name')
              // или
              $qb->andWhere('u.email = :email')
                ->orWhere('u.age > :age')

setParameter()

Метод setParameter() используется для связывания параметра с реальным значением. Это предотвращает SQL-инъекции, так как значения не подставляются напрямую в запрос, а передаются как параметры. 

            
              $qb->setParameter('name', 'John');

В приведенном примере параметр :name будет заменен значением 'John'

orderBy()

Метод orderBy() используется для сортировки результатов. Вы указываете поле, по которому будет производиться сортировка, и направление сортировки (ASC — по возрастанию, DESC — по убыванию). 

            
              $qb->orderBy('u.name', 'ASC')

join() и leftJoin()

Методы join() и leftJoin() используются для объединения сущностей. В отличие от обычных SQL-запросов, где вы пишете JOIN, здесь используется объектно-ориентированный подход. 

            
              $qb->join('u.profile', 'p');
              $qb->leftJoin('u.orders', 'o')

join() создаст стандартный INNER JOIN, а leftJoin() — LEFT JOIN.

getQuery()

После того как все части запроса собраны, вы можете использовать метод getQuery(), чтобы получить объект Query, который выполняет запрос. 

            
              $query = $qb->getQuery();
              $results = $query->getResult();

limit() и offset()

Методы limit() и offset() позволяют управлять количеством возвращаемых результатов и реализовывать пагинацию. 

            
              $qb->setMaxResults(10)  // Ограничение на 10 записей
                ->setFirstResult(20) // Смещение на 20 записей

Ещё один пример Query Builder

            
              $qb = $userRepository->createQueryBuilder('u');

              $qb->select('u')
                 ->where('u.name = :name')
                 ->andWhere('u.createdAt > :date')
                 ->setParameter('name', 'John')
                 ->setParameter('date', new \DateTime('2020-01-01'))
                 ->orderBy('u.name', 'ASC');
              
              $query = $qb->getQuery();
              $users = $query->getResult();

Пример QB с Join

            
              $qb = $userRepository->createQueryBuilder('u');

              $qb->select('u', 'p')
                 ->join('u.profile', 'p')
                 ->where('p.status = :status')
                 ->setParameter('status', 'active');
              
              $query = $qb->getQuery();
              $users = $query->getResult();
